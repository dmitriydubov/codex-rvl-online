# Независимое ревью Grok AI: data-reference

Дата: 2026-10-07. Основание: `main` `503ecb5`.

Это ревью готового модуля, а не отдельного PR. Код сервиса здесь не меняется. Гейты заново не гонялись: цифры приёмки в плане не пересчитывались.

Вердикт: **готов к выкатке с остаточными рисками ниже**. Открытых блокеров нет.

## Что это

`data-reference` принимает сообщения 1С, хранит сырьё и отдаёт справочники соседям. Разбор идёт после приёма, а не вместе с ним. Поток не держит сообщение, которое ждёт родителя. Последнее полученное сообщение решает за запись.

Пакеты: `config`, `controller`, `dto`, `entity`, `exception`, `mapper`, `repository`, `service`. Сущности создаются фабрикой, конструктор вызывает только `super`.

## Что держится

Проверено по коду в ревью PR, а не по описаниям.

- Деньги: сначала знаки после запятой, потом длина целой части. Причина называет поле и не цитирует значение.
- Процент сооплаты и программы: одно правило 0–100, копии в маппере нет.
- Целое за пределом `int` отклоняется с именем поля. Сырьё читается своей фабрикой с пределом 147 455 цифр. REST и приём из очереди остаются на 1000.
- Ребёнок без родителя ждёт его и не держит поток. Чужой родитель помнится, его дети пропускаются сразу. Применённое и пропущенное сообщение закрывает старые ожидания той же записи. Повтор после ручного возврата начинает срок заново. Отказ после фиксации исход не переписывает.
- Передача прайса читает части до блокировки строки услуги, короткой транзакцией только для чтения.
- ПДн полиса: стираются ФИО, дата рождения и почта после запаса. Номер, даты, пол и программы остаются. R-05 отвечает 200 с `null` и `personal_data_erased`. Новое сообщение приносит ПДн снова.
- Действующий договор и строка условий считаются по датам, границы включительно. Пустая дата окончания — бессрочно.
- Перечень программы читается отдельным запросом с устойчивым `order by`. Шапка и перечень — один снимок повторяемого чтения.
- Кэш справочника сбрасывается после коммита. 404 не кэшируется. Поиск полисов не кэшируется.
- Журнал и `toString()` полиса не цитируют ФИО, дату рождения, пол, почту и номер.

## Остаточные риски

Не блокеры. Часть уже принята владельцем.

1. Уже сохранённая сооплата вне 0–100 остаётся, пока 1С не пришлёт полис заново. После выкатки: `select count(*) from policy_services where copayment not between 0 and 100`.
2. Тело из очереди с числом длиннее 1000 цифр не читается, доставка подтверждается, след — ERROR и счётчик неопознанной доставки.
3. Дробь в целом поле молча обрезается. Номер строки адреса санатория за пределом целого разбор не роняет.
4. Дети санатория без РВЛ, о котором сервис не помнит, ждут срок и уходят в FAILED.
5. Пересмотр, записавший ровно ту же строку, уйдёт в повтор. Чужая правка строки между выборкой и отказом сочтётся фиксацией.
6. Части прайса читаются дважды. При нескольких репликах вложенное соединение нужно считать против пула.
7. Кэш в памяти процесса. Сообщение 1С сбрасывает только реплику, которая его разобрала. Остальные отстают до срока жизни записи.
8. Запрос ровно в полночь может положить ответ нового дня под ключ прошлого.
9. Полис с открытой датой стирает ПДн только после архива. Пол остаётся. Откат миграции 019 возможен только до первого стирания.
10. Сравнение наименований зависит от правила сравнения строк в базе контура.
11. Фичи со сроком договора 2030-12-31 с 2031 года начнут отвечать 404. Это долг тестовых данных, не контура.
12. `OneCEntity` не abstract. Код пакета может создать его напрямую. В `src/main` таких вызовов не видел.

- Не смотрел секреты, сеть и выкатку.
