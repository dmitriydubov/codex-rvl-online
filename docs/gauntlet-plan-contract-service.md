### 2.2. Сверка шагов с документами и текущим кодом (2026-10-07)

Что изменилось против разделов 3.9–3.10 общего плана и почему:

1. **Таймауты клиента К2a пересчитаны.** С Ш64 и Ш69 (2026-10-07) ожидание соединения в пулах data-reference — 2 с, лимит
   REST-чтения — 3 с, сетевой тайм-аут пула REST — 5 с: худший ответ ≈ 5 с, таймаут чтения клиента Договоров — от 7 с.
   Прежняя карточка К2a (connectionTimeout 30 с, socketTimeout 60 с) устарела. Значения — ответ О8 (раздел 6).
2. **`RestClient` без новых зависимостей — только вручную.** По `./gradlew dependencies --configuration runtimeClasspath`
   data-reference (2026-10-07) в classpath Boot 4.0.7 через `spring-boot-starter-web` нет модуля `spring-boot-restclient`:
   автонастроенный бин `RestClient.Builder` и свойства `spring.http.clients.*` (connect-timeout, read-timeout) даёт
   `spring-boot-starter-restclient` (есть в BOM 4.0.7; в Nexus контура не проверялся). Сам класс `RestClient` — в
   `spring-web` (Spring Framework 7.0). Выбор — РК1 (раздел 7): (а) `RestClient.builder()` из spring-web с
   `JdkClientHttpRequestFactory` и своими `@ConfigurationProperties` таймаутов, без новой зависимости; (б) новая зависимость
   `org.springframework.boot:spring-boot-starter-restclient:4.0.7` после проверки в Nexus. Рекомендация — (а): правило
   «Nexus отдаёт не все модули Boot 4» уже стоило отказа от webmvc-стартеров.
3. **Ретраи К2a — средствами Spring Framework 7.0.** `@Retryable` / `RetryTemplate` (`org.springframework.resilience`,
   включается `@EnableResilientMethods`): по умолчанию 3 повтора с паузой 1 с, перечень исключений — `includes`/`excludes`,
   `MethodRetryPredicate` для «повторять только на 503 и на 404 ещё не пришедшего полиса». Источник —
   docs.spring.io/spring-framework/reference/core/resilience.html (метатег версии 7.0.9 при сборке 7.0.8). Spring Retry как
   отдельная зависимость не нужен.
4. **Второй брокер в Boot 4.0.** Boot автонастраивает одну `CachingConnectionFactory` из `spring.rabbitmq.*`; второй брокер —
   свои бины `CachingConnectionFactory`, `RabbitTemplate` и `SimpleRabbitListenerContainerFactory` на своих
   `@ConfigurationProperties`, либо `SimpleRoutingConnectionFactory` (Spring AMQP 4.0, «Routing Connection Factory»).
   Выбор — РК2 (раздел 7); рекомендация — отдельные фабрики на брокер, без маршрутизации по thread-bound ключу: у
   слушателей и публикаций разные брокеры статически.
5. **Стартеры OAuth2 в Boot 4 переименованы.** В BOM 4.0.7 есть и `spring-boot-starter-oauth2-client`, и

## 8. Задача для Jira — К3 (черновик, на апрув владельца)

**Тема.** contract-service: приём задачи на выпуск от сервиса Заявок и прекращение работы по заявке.

**Что и зачем.** Сервис Договоров начинает делать свою основную работу: принимать из очереди сервиса Заявок задачу на
выпуск по заявке и решать, что выпускается по каждому участнику поездки. Для этого в сервисе появляются таблицы
договоров КМ, полисов ЛМ, сторон договора и журнала входящих сообщений; слушатель очереди, который сохраняет сообщение
в журнал и подтверждает брокеру только после записи (повтор того же сообщения не создаёт дубля, устаревшая версия
пропускается); обработчик по расписанию с тремя попытками и паузами 1, 5 и 15 минут, после которых сообщение помечается
как необработанное и об этом сообщает метрика. По задаче на выпуск сервис разбирает состав: застрахованный без доплаты —
ничего не выпускается, с доплатой — договор КМ, родственник без доплаты — полис ЛМ, с доплатой — договор КМ; сохраняет
снимок сторон, даты и сумму, присваивает номер договора КМ; при повторной задаче с большей версией добавляет новых
участников, прекращает работу по исчезнувшим и перевыпускает проект при изменении сумм. По сообщению о прекращении
работы все договоры и полисы заявки переводятся в «прекращено» с причиной, история сохраняется. Ответы сервису Заявок о
статусах в этом шаге не отправляются (их добавит следующий шаг с исходящей очередью). Попутно адрес сервиса справочных
данных становится обязательной настройкой без умолчания, а один класс клиента справочников переименовывается по итогам
предыдущего шага.
