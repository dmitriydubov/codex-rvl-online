Функция: Сообщение передачи связей застрахованных без массива строк отклоняет передачу целиком, связи не удаляются

  Строки связей застрахованных 1С:УСК присылает в сообщении со строками массивом recordSet. Сообщение, в котором поля
  recordSet нет, оно равно null или записано не массивом, — не сообщение без строк, а нарушение контракта: иначе
  передача с финальным сообщением «сообщений 1, строк 0» собралась бы как пустая и в режиме «Замещение» удалила бы все
  связи по отбору. Дата-референс отклоняет такую передачу целиком и без повторов: у сообщения со строками — причина с
  именем поля, без значения; у финального сообщения — ссылка на него, а если оно пришло позже — «передача уже
  отклонена». Прежние связи застрахованного остаются.

  Предыстория:
    Дано 1С:УСК прислала договор страхования ДМС:
      | external_id | 77ff17b5-e659-4720-b57f-e8a19c00fcea |
      | номер       | СТЕНД-ДМС-0001                       |
      | начало      | 2026-01-01T00:00:00                  |
      | окончание   | 3000-01-01T00:00:00                  |
    И 1С:УСК прислала полис:
      | external_id | 11111111-2222-4333-8444-555555555501 |
      | номер       | СТЕНД-0001                           |
      | договор     | 77ff17b5-e659-4720-b57f-e8a19c00fcea |
      | начало      | 2026-01-01                           |
      | окончание   | 3000-01-01                           |
    И 1С:УСК прислала полис:
      | external_id | 11111111-2222-4333-8444-555555555502 |
      | номер       | СТЕНД-0002                           |
      | договор     | 77ff17b5-e659-4720-b57f-e8a19c00fcea |
      | начало      | 2026-01-01                           |
      | окончание   | 3000-01-01                           |
    И 1С:УСК прислала полную передачу связей застрахованных с отбором "idInsured=11111111-2222-4333-8444-555555555501":
      | застрахованный                       | связанный полис                      | тип связи                            | начало                    | окончание                 |
      | 11111111-2222-4333-8444-555555555501 | 11111111-2222-4333-8444-555555555502 | 797093be-2c51-11e8-8123-005056b43f21 | 2026-01-01T00:00:00+03:00 | 3000-01-01T00:00:00+03:00 |
    И Дата-референс разобрал присланные сообщения

  # [В-Ш91-RS], [К-302]: сообщение со строками без массива recordSet — ошибка контракта с именем поля, а не сообщение без
  # строк ([ТЗ-11] «Сообщение со строками»: recordSet — обязательный массив); передача отклоняется целиком без повторов,
  # прежние связи не трогаются ([ЗАД91] п. 2). Финальное сообщение пришло первым и ждёт в буфере; сообщение с ошибкой
  # отклоняет и его ([РВ] п. 7): у сообщения со строками — своя причина, у финального — ссылка на него ([ТЗ-11]
  # «Ошибки»). Причина называет поле recordSet без значения ([ТЗ-11] «Ошибки», [DR-ПДн], [РВ] п. 4); запись ERROR — у
  # сообщения с ошибкой ([РВ] п. 8). Прежняя связь A с P1 остаётся ровно такой, как была. Без правила сообщение без
  # поля, с null или со строкой считалось бы сообщением без строк, передача «сообщений 1, строк 0» собралась бы пустой и
  # удалила все связи A по отбору ([К-302]); строка, записанная объектом, разбиралась бы как набор строк, и причина
  # назвала бы не то поле.
  Структура сценария: Сообщение со строками без массива строк пришло после финального «сообщений 1, строк 0» — отклонены оба, связи застрахованного не удалены
    Дано 1С:УСК прислала финальное сообщение "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee12" передачи связей застрахованных "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee01" с отбором "idInsured=11111111-2222-4333-8444-555555555501": сообщений 1, строк 0
    И 1С:УСК прислала сообщение со строками "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee11" передачи связей застрахованных "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee01" с отбором "idInsured=11111111-2222-4333-8444-555555555501" без массива строк: "<дефект>"
    Когда Дата-референс разбирает присланные сообщения
    Тогда последнее сообщение 1С:УСК отклонено без повторов с причиной "<причина>"
    И сообщение 1С:УСК "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee12" отклонено без повторов с причиной "передача aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee01 отклонена: ошибка в сообщении aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee11: <причина>"
    И в журнале Дата-референса есть запись уровня ERROR об окончательном отказе последнего сообщения: поток "связи застрахованных", попытка 1, тип "OneCFieldException", SQLSTATE "нет"
    И связи застрахованного "11111111-2222-4333-8444-555555555501" в базе Дата-референса:
      | связанный полис                      | тип связи                            | начало     | окончание |
      | 11111111-2222-4333-8444-555555555502 | 797093be-2c51-11e8-8123-005056b43f21 | 2026-01-01 | нет       |

    Примеры:
      | дефект             | причина                             |
      | нет поля recordSet | нет обязательного поля recordSet    |
      | recordSet — null   | нет обязательного поля recordSet    |
      | recordSet — объект | поле recordSet не является массивом |
      | recordSet — строка | поле recordSet не является массивом |

  # [В-Ш91-RS], [ТЗ-11], [ЗАД91] п. 2 — как выше; порядок двух очередей не гарантирован ([ТЗ-11] «Сборка передачи»).
  # Сообщение со строками пришло первым: оно отклоняется сразу при приёме, не дожидаясь финального ([РВ] п. 7), а
  # финальное сообщение приходит к уже отклонённой передаче — «передача <cid> уже отклонена» ([РВ] п. 3, как у прайсов).
  # Порядок частей меняет причину у финального сообщения, поэтому закреплены оба порядка. [РВ] п. 8: запись ERROR — у
  # сообщения с ошибкой. Без правила сообщение ждало бы в буфере как сообщение без строк, и на финальном «сообщений 1,
  # строк 0» передача собралась бы пустой и удалила все связи A по отбору.
  Структура сценария: Сообщение со строками без массива строк пришло раньше финального — отклонено сразу, финальное получает «уже отклонена», связи застрахованного не удалены
    Дано 1С:УСК прислала сообщение со строками "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee11" передачи связей застрахованных "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee01" с отбором "idInsured=11111111-2222-4333-8444-555555555501" без массива строк: "<дефект>"
    И 1С:УСК прислала финальное сообщение "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee12" передачи связей застрахованных "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee01" с отбором "idInsured=11111111-2222-4333-8444-555555555501": сообщений 1, строк 0

    Тогда сообщение 1С:УСК "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee11" отклонено без повторов с причиной "<причина>"
    И последнее сообщение 1С:УСК отклонено без повторов с причиной "передача aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee01 уже отклонена"
    И в журнале Дата-референса есть запись уровня ERROR об окончательном отказе сообщения "aaaaaaaa-bbbb-4ccc-8ddd-eeeeeeeeee11": поток "связи застрахованных", попытка 1, тип "OneCFieldException", SQLSTATE "нет"
    И связи застрахованного "11111111-2222-4333-8444-555555555501" в базе Дата-референса:
      | связанный полис                      | тип связи                            | начало     | окончание |
