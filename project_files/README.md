# Документы контура РВЛ ОНЛАЙН

Источники предметной области: ТЗ, схемы, структуры данных. Разложены по сервисам.

| Каталог | Что внутри |
|---|---|
| `common/` | документы контура целиком и соседей: схемы процесса и флоу, ФТ к модулю РВЛ, вопросы и ответы, точки интеграции с 1С:УСК, структура данных сервиса Заявок |
| `data-reference/` | сервис справочных данных: журнал решений REST — основной источник правил REST; действующие редакции ТЗ API и структуры БД (`edited/`), исходные версии ТЗ API от 21.09.2026 и структуры БД v.0.1 и v.0.2, потоки 1С:УСК ТЗ-01…ТЗ-10 (`1C_data/`), копии документов с предлагаемыми правками (`edit/`) |
| `contract-service/` | сервис Договоров: журнал решений Договоров (с 2026-10-13; при расхождении с ТЗ прав журнал); действующие редакции ТЗ (`edited/`): точки интеграций Договоров и Заявок (ДГ-01…ДГ-07), синхронные эндпоинты (СЭ-01…СЭ-04), структура данных Договоров; их первые редакции (PDF) и запись первой правки 2026-10-22 с выделениями (`edit/`); требования к лендингу и ЛК (`requirements_landing_lk (003).docx`), документы Ordering (`ordering/`), копии контрактов и потоков 1С под номерами KDMS (`1C_data/`) |

Новые редакции ТЗ сервисов владельца владелец переносит в Confluence; правятся только ТЗ его сервисов, документы
1С:УСК и соседей остаются как есть (предлагаемые правки к ним — копии в `edit/`). У `data-reference` новая редакция —
`data-reference/edited/`: Markdown-исходник (его правят в PR) и `.docx` рядом, собранный
`python3 project_files/md2docx.py "<файл.md>"` (нужен Python-пакет `markdown`, вывод воспроизводимый). У
`contract-service` так же — `contract-service/edited/` (правило — `contract-service/CLAUDE.md`).

В рабочий контур каталог не переносится: в документах есть персональные данные и внутренние адреса.
