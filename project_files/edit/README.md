# Копии ТЗ с предлагаемыми правками

Здесь лежат копии PDF из `project_files/` с жёлтыми выделениями мест, которые расходятся с тем, что сервис
`data-reference` делает по решениям владельца. У каждого выделения в PDF есть пояснение (видно при наведении или в панели
комментариев), в конце каждого PDF — сводная страница со всеми правками; ниже тот же перечень в тексте. Оригиналы не
трогались: правки — предложение к новой редакции документов. Источник правил — `../Журнал решений REST.md`
(восстановлен из кода и утверждён владельцем 2026-10-05, когда автор ТЗ покинул компанию).

Рядом с каждым PDF лежит тот же документ в Word (`.docx`) для импорта в Confluence: текст ТЗ восстановлен из PDF
(заголовки, абзацы, код, таблицы), те же фрагменты выделены жёлтым, пояснение к каждому — комментарием Word, привязанным
к выделенному тексту; в конце — сводка правок. Вёрстка Word упрощена по сравнению с PDF (картинки и нумерация
списков из PDF не переносятся), по смыслу тексты совпадают.

Как сделано: `pymupdf` 1.28 ищет фрагмент текста на странице и ставит на него аннотацию-выделение с пояснением; Word
собирается библиотекой `docx` (npm) из того же перечня. Скрипты и перечень правок — у координатора серии, при новой
редакции ТЗ перечень обновляется вместе с журналом.

## «Сервис договоров_синхронные эндпоинты — правки 2026-10-05.pdf»

Копия «Сервис договоров. Синхронные эндпоинты» с правками только в части, касающейся Дата-референса (раздел «Чтение справочников Дата-референса» и общие правила). Документ принадлежит команде сервиса Договоров; выделения — то, что нужно согласовать с его разработчиком (план, О8).

| Стр. | Что выделено | Правка и почему |
|---|---|---|
| 1 | `ISO 8601 с часовым поясом` | **Даты у Дата-референса — yyyy-mm-dd.** Дата-референс отдаёт даты как yyyy-mm-dd (так в «Общих соглашениях» ТЗ API и в его спецификации); открытая дата 1С — null. В разделе о чтении справочников это стоит оговорить, чтобы клиент Договоров не ждал часового пояса. |
| 6 | `GET /policies/{id}` | **Полис для Договоров — проекция без ПДн.** Договорам нужны номер, external_id и период — ровно это отдаёт GET /internal/v1/policies/{id}/contract-view (и GET /internal/v1/policies/contract-view?external_id={uuid} — найти наш id по GUID 1С после регистрации полиса). GET /internal/v1/policies/{id} отдаёт ФИО, дату рождения, пол и e-mail и предназначен сервису Заявок; Договорами не читается (решение Р20 (а)). В ответе также is_archive. |
| 6 | `GET /insurance-contracts/{id}` | **Договор страхования: адрес и состав.** GET /internal/v1/insurance-contracts/{id}; есть и поиск по GUID 1С: ?external_id={uuid}. Ответ: id, external_id, number, begin_date, end_date, is_archive, insurer {id, external_id, name, full_name, inn, kpp} — наименований два, краткое и полное; insurer = null, если страхователь физлицо. 404 — INSURANCE_CONTRACT_NOT_FOUND (CONTRACT_NOT_FOUND у Договоров занят договором КМ). |

| 7 | `REFERENCE_UNAVAILABLE` | **Соответствие кодов.** REFERENCE_UNAVAILABLE — код сервиса Договоров для своего ответа Заявкам; от Дата-референса при этом приходит 503 SERVICE_UNAVAILABLE (а 404 POLICY_NOT_FOUND на ещё не пришедший полис — повод повторить, а не отказ выпуска). |
